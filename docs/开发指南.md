# OVPN-MANA 二次开发指南

> 版本: 1.0.0.1 | 语言: C++17 | 构建: CMake + vcpkg | 目标平台: Linux (主) / Windows (辅)

## 一、项目概述

OVPN-MANA 是一个 OpenVPN 管理 SDK，以**动态库（.so / .dll）**形式对外暴露 C 风格 API，同时提供一个命令行管理工具 `openvpnmgr`。

**核心能力**：
- OpenVPN 服务全生命周期管理（创建/启停/删除）
- 客户端证书签发/吊销，在线客户端状态查询
- 基于 easy-rsa 的 PKI 证书自动化
- 跨语言调用支持（C ABI）

**适用场景**：
- Web 后台通过 FFI 调用管理 VPN 服务
- 运维脚本/自动化工具集成
- 作为其他 C/C++ 项目的子模块

## 二、架构设计

### 2.1 分层架构

```
┌──────────────────────────────────────────────┐
│              命令行工具 (main.cpp)              │  CLI 入口
├──────────────────────────────────────────────┤
│           C API 层 (ovpn-mana.cpp)             │  extern "C" 导出
│           类型定义 (sdk.types.hpp)              │  C 兼容结构体/错误码
├──────────────────────────────────────────────┤
│         业务逻辑层 (OpenVPNManager.cpp)         │  C++ 静态方法
├──────────────────────────────────────────────┤
│   系统调用 (systemctl / easyrsa / openvpn)     │  shell 命令
└──────────────────────────────────────────────┘
```

**设计要点**：
- **C API 层是稳定契约**：对外仅暴露 `ovpn-mana.hpp` 中的函数。内部重构时，只要 ABI 不变，调用方无需重新编译。
- **opaque handle 模式**：`ovpn_mana_handle_t` 实为 `void*`，内部 cast 为 `OpenVPNManager*`。调用方看不到 C++ 实现细节。
- **错误码统一**：所有 API 返回 `ovpn_err_t`，定义在 [sdk.types.hpp](file:///d:/Projects/20250427-ovn-mana/sdk-gitee/include/sdk.types.hpp#L30-L36)。

### 2.2 数据流（以"创建服务"为例）

```
用户调用 ovpn_mana_create_service(handle, "mysrv", "10.8.0.0", 1194)
  → C API 层: cast handle → OpenVPNManager*
  → OpenVPNManager::createService(name, subnet, port)
      → easyrsa gen-req / sign-req         （生成服务器证书）
      → openssl dhparam                    （DH 参数）
      → 拷贝 ca.crt / server.crt / .key 到 /etc/openvpn/server/<name>/
      → openvpn --genkey secret ta.key     （TLS 密钥）
      → 写入 <name>-server.conf            （生成 OpenVPN 配置）
      → systemctl start openvpn@<name>-server
      → systemctl enable openvpn@<name>-server
  → 返回 OVPN_ERR_SUCCESS
```

### 2.3 文件系统布局（运行时）

```
/etc/openvpn/
├── <name>-server.conf              # OpenVPN 服务配置
├── server/
│   └── <name>/
│       ├── ca.crt
│       ├── server.crt / server.key
│       ├── dh.pem / ta.key
│       ├── ipp.txt                 # IP 持久化池
│       ├── status.log              # 在线客户端状态
│       └── ccd/                    # 客户端配置目录
├── client-configs/
│   └── <serviceName>/
│       └── <clientName>.ovpn       # 分发给客户端的配置文件
└── crl.pem                         # 证书吊销列表

<easy-rsa>/pki/
├── ca.crt / issued/ / private/ / reqs/ / dh.pem / crl.pem
```

## 四、核心接口详解

### 4.1 生命周期管理

```cpp
// 创建管理器实例（返回 opaque handle）
ovpn_mana_handle_t ovpn_mana_create();

// 销毁实例
void ovpn_mana_destroy(ovpn_mana_handle_t handle);
```

**二次开发注意事项**：
- `ovpn_mana_create()` 内部分配 `new OpenVPNManager()`，失败返回 `nullptr`。
- 当前 `OpenVPNManager` 所有方法均为 `static`，实例本身**无状态**。若未来需要状态管理（如连接池、缓存），可在此实例上扩展成员变量。

### 4.2 服务管理

| API | 功能 |
|-----|------|
| `ovpn_mana_list_services` | 列出所有由本 SDK 创建的服务 |
| `ovpn_mana_create_service` | 创建服务（name, subnet, port） |
| `ovpn_mana_start_service` | 启动服务 |
| `ovpn_mana_stop_service` | 停止服务（含重试确认） |
| `ovpn_mana_restart_service` | 重启服务 |
| `ovpn_mana_delete_service` | 删除服务（停止→禁用→删文件→吊销证书→更新CRL） |

**创建服务的完整流程**（[OpenVPNManager.cpp](file:///d:/Projects/20250427-ovn-mana/sdk-gitee/src/OpenVPNManager.cpp#L71-L190)）：
1. `getuid() == 0` 权限检查
2. `easyrsa gen-req` + `easyrsa sign-req` 签发服务器证书
3. 生成 dh.pem（如不存在）
4. 创建 `ccd/` 目录
5. 拷贝证书链到 `/etc/openvpn/server/<name>/`
6. 生成 `ta.key`（TLS Auth）
7. 写入 `.conf` 配置文件
8. `systemctl start` + `systemctl enable`

### 4.3 客户端管理

| API | 功能 |
|-----|------|
| `ovpn_mana_create_client` | 创建客户端（签发证书 + 生成 .ovpn 文件） |
| `ovpn_mana_revoke_client` | 吊销客户端（吊销证书→更新CRL→重启服务→删文件） |
| `ovpn_mana_get_online_clients` | 解析 `status.log` 获取在线客户端列表 |
| `ovpn_mana_get_total_clients_count` | 统计 `client-configs/` 下 `.ovpn` 文件数 |
| `ovpn_mana_get_client_config` | 返回 `.ovpn` 文件内容（供下载分发） |

**`ovpn_mana_get_online_clients` 调用模式**：

```cpp
// 先传 nullptr 获取数量
int count = 0;
ovpn_mana_get_online_clients(handle, "mysrv", nullptr, count);

// 再分配内存获取数据
ovpn_client_t *clients = new ovpn_client_t[count];
ovpn_mana_get_online_clients(handle, "mysrv", clients, count);
// ... 使用 clients ...
delete[] clients;
```

这种两阶段调用模式在需要扩展分页/过滤时保持兼容。

## 七、关键实现细节

### 7.1 命令执行 (`execCommand`)

[OpenVPNManager.cpp](file:///d:/Projects/20250427-ovn-mana/sdk-gitee/src/OpenVPNManager.cpp#L22-L36) 中使用 `popen()/pclose()` 执行 shell 命令。Windows 下宏替换为 `_popen/_pclose`。

**风险点**：
- 无超时机制，可能导致调用方阻塞
- 命令字符串拼接存在注入风险（用户输入未做转义）

**改进方向**：
```cpp
// 建议：添加超时 + 参数校验
static bool execCommand(const std::string &cmd, std::string &output,
                        std::chrono::seconds timeout = std::chrono::seconds(30));
```

### 7.2 status.log 解析

`getOnlineClients()` 解析 OpenVPN 的 `status.log` 文件。该文件格式：

```
OpenVPN CLIENT LIST
Updated,...
Common Name,Real Address,Bytes Received,Bytes Sent,Connected Since
client1,1.2.3.4:5678,12345,67890,Sat Jun 14 10:30:00 2025
ROUTING TABLE
Virtual Address,Common Name,Real Address,Last Ref
10.8.0.2,client1,1.2.3.4:5678,...
GLOBAL STATS
Max bcast/mcast queue length,0
END
```

**注意事项**：
- 不同 OpenVPN 版本格式略有差异，需做兼容
- 大并发场景下文件可能较大，考虑增量读取

### 7.3 平台兼容

| 特性 | Linux | Windows |
|------|-------|---------|
| 进程执行 | `popen/pclose` | `_popen/_pclose`（宏替换） |
| 权限检查 | `getuid()` | 返回 0（跳过检查） |
| systemctl | `/bin/systemctl` | 不支持 |
| easy-rsa | `.sh` 脚本 | 不支持 |
| 构建 | Make / Ninja | MSVC + vcpkg |

**当前 Windows 支持不完整**，systemctl 和 easy-rsa 调用在 Windows 上无法工作。若需 Windows 支持，需：
- 用 Windows Service API 替代 systemctl
- 用原生 OpenSSL 调用替代 easy-rsa shell 脚本

## 八、安全注意事项

1. **Root 权限**：所有操作需 root，调用方（如 Web 应用）需通过 sudo 或 setuid 提权，切勿让 Web 进程本身以 root 运行。
2. **命令注入**：`execCommand` 直接拼接用户输入到 shell 命令。服务名/客户端名等参数必须做白名单校验（当前仅在 CLI 层有端口号范围检查）。
3. **文件权限**：`.key` 文件应为 `600`，`.crt`/`.pem` 应为 `644`。CMakeLists.txt 中已有 install 阶段的 chmod 脚本。
4. **证书私钥**：私钥文件不应通过网络明文传输。`.ovpn` 分发文件内含私钥，建议通过 HTTPS + 一次性链接分发。

## 十一、性能与稳定性

### 当前瓶颈

| 操作 | 耗时估算 | 原因 |
|------|---------|------|
| 创建服务 | 5-30s | easy-rsa 密钥生成（含 DH 参数） |
| 创建客户端 | 3-10s | easy-rsa 证书签发 |
| 删除服务 | 2-5s | 多步串行操作 |
| 列出在线客户端 | <100ms | 纯文件解析 |

### 改进建议

1. **异步操作**：创建/删除等长耗时操作应支持异步回调模式
2. **命令缓存**：频繁读取的 status.log 可用 inotify 监听 + 内存缓存
3. **连接池**：`popen` 开销较大，可考虑复用进程或改用 socket 通信

## 十二、贡献规范

1. 代码风格：遵循现有风格（4 空格缩进、`PascalCase` 类名、`camelCase` 方法名）
2. C API 层不允许抛异常，所有错误通过返回码传递
3. C++ 层可使用异常，但必须在 C API 层 `catch`
4. 公共头文件注释必须完整（Doxygen 格式，含 `@brief` `@param` `@return` `@note`）
5. 新增 API 需同步更新 `main.cpp` CLI 和本文档
