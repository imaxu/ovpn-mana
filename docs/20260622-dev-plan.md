**接口设计**（`Validators.hpp`）：

```cpp
#pragma once
#include <string>
#include <string_view>

namespace ovpn::validators {

struct ValidationResult {
    bool valid;
    std::string reason;  // 校验失败时的人类可读原因
};

ValidationResult validateName(std::string_view name);
ValidationResult validateServiceName(std::string_view name);
ValidationResult validateClientName(std::string_view name);
ValidationResult validateIPv4(std::string_view ip);
ValidationResult validateSubnet(std::string_view subnet);
ValidationResult validatePort(int port);

} // namespace ovpn::validators
```

**校验规则汇总**：

| 函数                    | 规则                                                              |
| ----------------------- | ----------------------------------------------------------------- |
| `validateName`          | 长度 1-64，白名单 `[a-zA-Z0-9_.-]`，字母数字开头，禁止 `;$\`\\|&'"`，禁止 `../` `./` |
| `validateServiceName`   | `validateName` + 禁止 `-server` 后缀                                |
| `validateClientName`    | `validateName` 别名，语义一致                                       |
| `validateIPv4`          | 4 段 0-255，无前导零，`inet_pton` 或无依赖手写解析                  |
| `validateSubnet`        | CIDR 格式 `x.x.x.x/8-30`，主机位必须全零，前缀 8-30                |
| `validatePort`          | 范围 1024-65535（避免 Linux 特权端口）                              |

**实现要点**：

- `validateName` 采用白名单正则 + 黑名单字符双重检查，防御 shell 注入和路径穿越
- `validateIPv4` 手写解析，不依赖 `inet_pton`（避免 Windows 上需要 Winsock 初始化）
- 所有函数返回 `ValidationResult`，包含 `valid` 布尔值和 `reason` 字符串

**测试用例**（23 个，详见重构规划文档第 15.8 节）：

| 测试组                       | 用例数 | 覆盖场景                                       |

| `ValidateServiceName`        | 2      | 拒绝 `-server` 后缀、接受其他后缀               |
| `ValidateIPv4`               | 3      | 合法 IP、越界、前导零、畸形格式                 |

bool isIPConflict(const std::string& ip, const std::string& ccdDir) {
    for (const auto& entry : fs::directory_iterator(ccdDir)) {
        std::ifstream f(entry.path());
        std::string line;
        while (std::getline(f, line)) {
            if (line.find("ifconfig-push") != std::string::npos &&

## 四、风险与缓解措施

| 风险                                  | 等级 | 影响                              | 缓解措施                                                     |
| ------------------------------------- | ---- | --------------------------------- | ------------------------------------------------------------ |
| `config.hpp` 移除导致编译错误遗漏    | 中   | 部分文件仍引用旧常量，编译失败    | 使用 `grep` 全局搜索 `EASY_RSA_DIR\|OVPN_DIR\|OPENVPN_BIN\|SYSTEMCTL_BIN\|OVPN_SERVER_CONF_DIR` 确认无残留 |
| 静态方法改实例方法导致调用方编译失败  | 中   | 外部 C++ 调用方直接使用 `OpenVPNManager::` 静态调用 | C API 层保持不变，仅 C++ 头文件变更；若存在外部 C++ 调用方需提前沟通 |
| Windows 控制台 ANSI 不支持            | 低   | CLI 颜色输出显示乱码              | 启动时调用 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`，失败时降级为无颜色输出 |
| `std::filesystem` 在旧编译器不兼容   | 低   | 部分编译器不支持 C++17 filesystem | 当前已使用 `std::filesystem`，无新增风险；若需支持 GCC < 8，需链接 `-lstdc++fs` |
| CCD IP 冲突检测性能                   | 低   | 大量客户端时遍历 O(n)             | 客户端数量通常 < 100，O(n) 遍历可忽略；若超 1000 可建立内存索引 |
| 配置注入后多实例并发安全              | 低   | 多线程同时调用同一个 handle        | 当前设计为每个 handle 持有独立 `AppConfig`，无共享状态；多线程安全由调用方保证 |
